# 📰 报刊回声 Press Echo

SillyTavern 第三方扩展：**文学与报刊特化的世界推演**。

故事里的主角发表作品以后，扩展会推演“谁会在哪一天、在哪份报刊、以什么形式回应”：正式书评、书讯短评、短讯八卦、论战文章、私信、读者来信，以及各报的转载和提及（剪报）。扩展会识别当前故事的年代，检索那个年代的资料，让生成的文字符合那个时代。

## 设计原则

**谁回应、哪天回应、褒还是贬，由规则决定；模型只负责把已经批准的事件写成文字。**

推演部分不调用模型，结果写进账本，随聊天保存，并用固定随机种子保证可复现。重新生成（swipe）回复、换个问法追问，都不会让“到底有几篇书评”跟着变。

## 安装

1. 把整个 `st-press-echo` 文件夹放进
   `SillyTavern/public/scripts/extensions/third-party/`
   （也可以先传到你自己的 GitHub 仓库，再在酒馆里用“安装扩展”填仓库地址）。
2. 刷新酒馆。右下角会出现报纸图标的圆形按钮（与书信簿的信封按钮同款，默认在它上方）；扩展设置里也有“报刊回声”抽屉。

**界面操作**：悬浮按钮按住可拖到任意位置；面板按住标题栏拖动，拖右下角调整大小，位置和大小都会记住。双击标题栏或点 ⤢ 恢复默认。

## 第一次使用

最省事的做法：打开“导入与整理”页，把材料放进去，让模型一次整理好。

1. **放材料**：拖进“一键整理”区，或点按钮添加。
   - 聊天记录：.txt，或酒馆导出的 .jsonl；也可以点“加入当前聊天记录”，可只取最近几楼。
   - 书信簿备份 .json：信件会交给模型整理，同时读进书信簿联动。
   - 世界书、粘贴的设定或笔记。
   - 作品原文：文件名带日期的 txt（`长子-回声报1890-4-15.txt`），会按文件名排好刊物和首发日期，不经过模型。
2. **开始整理**：插件把材料分段交给已连接的模型，抽出笔名、刊物、人物、作品、已经发生的反响、谁读过什么、传闻和当前故事日期，合并成一份“整理包”。面板会先估算要调用几次模型。
3. **看预览、点应用**：预览会列出每类新建多少、更新多少，以及需要你注意的地方，例如自动新建的刊物还缺出刊周期。可以按类别取消勾选。应用时：
   - 已有的条目只补充、更新，不会删掉你填过的内容；
   - 导入的反响记为已发生，直接入账；
   - 故事日期直接设为整理包里的日期，之前的事以整理包为准，不再重新推演。
4. **回溯推演**：导入只记下“已经发生的事”。要补上从第一部作品发表到现在的文学界变化，在“概览”点“回溯推演”：
   - **只补看不见的部分**（推荐）：导入的剪报、来信、私信视为当时的全部，不会冒出主角没见过的报道或没收到过的信。补出的是谁读过哪部作品、私下怎么看、圈子里怎么谈，以及以后会不会对旧作发声。
   - **全部补**：导入的记录不全时用，补出的书评、私信、转载标着“回溯”，进待审核，不自动入账。
5. **补关键字段**：到“人物与刊物”看一眼刊物的出刊周期、人物的身份和私交，这几项决定之后的推演。
6. 继续聊天，之后的反响由插件推演。

**聊天记录很长时**（几千楼），插件逐段整理会很慢、耗费也多。可以改用外部 AI：

1. 点“复制提示词”，发给 Claude、ChatGPT、Gemini 这类长上下文的聊天 AI；
2. 再把聊天记录发给它；
3. 它输出的 JSON 贴回插件点“读取”，或存成 .json 拖进来。

分几次输出也没关系，插件会按名字合并。格式说明见 [FORMAT.md](FORMAT.md)，也可以在面板里下载。

## 推演规则（v0.2：四关漏斗）

作品发表后，每个人物都要依次过四关。每一关只掷一次骰子，结果记进“阅读记录”，可以随时点“为什么？”查看理由。

1. **接触**：他有没有机会看到这部作品。
   - 途径：供职或常读发表它的刊物、私交好的朋友转告、坊间风声、读到别人已经批准的公开评论。
   - 人物的“常读刊物”默认是他供稿的刊物加上影响力 ≥4 的大报。
2. **阅读**：看到了读不读、读多少。
   - 取决于兴趣重叠、作品篇幅、此人近期是否忙（“忙碌期”字段），以及是否已经读过另一版本（如连载之后又出了单行本）。
3. **看法**：读了以后的褒贬方向和强弱（无所谓 / 有点看法 / 强烈）。
   - 具体内容这一步不让模型写，等到需要时才写。
4. **表达**：沉默、私下谈起、写私信，还是公开发表。
   - 公开发表还要过两道关：一是刊物版面，即每期的篇数上限；二是截稿日，即稿子要在出刊前几天交。
   - 赶不上就顺延到下一期；如果一直排不上，就作罢。

所以大多数人“读了但什么也没写”，这是正常的。阅读记录页会列出每部作品的人数：未接触、接触未读、读了一部分、读完。

另外三点规则：

- **日期**只会落在该刊物真实的出刊日，或此人的专栏日（例如法朗士在《时报》的周日专栏）。
- **未来的事件**会标为“已排期”，到期前对任何人都不可见。
- **声誉**按已批准的公开反响、按日期顺序重新计算。负面评论也带来知名度，只计一半负分。

### 分级自动通过

默认情况下，以下**次要事件**到期后会自动记入账本：转载提及、读者来信、短讯、书讯，以及虚构人物的私信。

以下事件**始终需要你确认**：正式书评、论战、真实历史人物的私信，以及涉及身份暴露的事件。

如果想全部手动审核，可以在设置里关掉。

### 证据卡与私下看法

- **证据卡**：在作品编辑页贴入原文，点“生成证据卡”。模型会把作品拆成编号要点（K1、K2……）。
- **私下看法**：之后生成看法、写书评时，每一条欣赏或批评都必须引用要点编号。
  - 提示词明确允许平淡的结果：觉得还行但没什么可说、只读懂一部分、认同论证但反对结论、认为不值得写。
  - 这样可以避免每个评论家都显得格外深刻或格外尖刻。

### 按楼层回滚

由某条消息触发推进时，扩展会先存一份快照。之后那条消息被删除、被改写或换了回复（swipe），推演会退回快照：

- 撤掉之后新生成的事件；
- 你手动录入的内容保留；
- 你审核过的事件（批准、驳回、写好的正文）会按事件键记下来，重推时生成同一条就沿用，不用重审。

改写或换回复时，如果识别出的日期没变，什么也不会发生。

## 单独推演：按作品、按人物

**按作品**：在“作品”页点某部作品的“推演”。会在数据副本上用不同的随机数推演几十次，不改动任何记录，然后列出：

- 每个人接触到、读、偏肯定还是偏批评、公开发表、写信、因此去找旧作的概率；
- 公开评论最可能出现在哪些刊物上；
- 点开某个人，可以看到其中一次推演的完整经过。

可以改刊物、改日期，看看“假如改投给《费加罗报》”“推迟到十月发表”会怎样；也可以设一个截止日期，只统计到那天为止。

**按人物**：在“人物与刊物”页点某人的“推演”，可以看到：

- 他和每部作品的关系：怎么接触到的、读了多少、怎么看、有没有由此开始追读；
- 他对每个笔名的**作者印象**；
- “假如他在某天读完某部作品”的预演：看法分布、会不会公开写、会不会写信、会不会去找其他作品、最可能找哪几部。确认确有其事，可以一键记为已发生。

**作者印象与追读**（在自动推进和回溯推演里同样生效）：

- **作者印象**：和人物的“欣赏/反感”分开记。“欣赏/反感”是长期口味；作者印象是读过之后对某个笔名的看法，每读一部就带日期累积一次，可升可降。推演某部作品时，只用发表日之前已经形成的印象，不会倒流。对一个笔名的印象不会转到另一个笔名上。
- **追读**：印象够好时，可能主动去找这位作者的旧作。同系列最想找（系列可在作品里填，留空则从书名推断）；题材对得上此人兴趣的次之；同署名但不相干的兴趣有限。旧作还要看找不找得到：成书和小册子好买，旧报纸要翻合订本。没找到的不算终结，下次再被勾起兴趣时会重试。印象达到“值得关注”以后，新作一出就有专门的“追读”渠道。
- **推荐**：读完觉得很好、看法又强烈的人，可能推荐给同一刊物的同事。

## 文学社交与看法连续性（v0.8）

**标签语义归类**：人物的关注、欣赏、反感和作品题材往往不是同一个词。在“人物与刊物”页点“用模型归类标签”，调用一次模型，把所有标签归进几十个概念组；之后推演就能认出“家庭责任”“长子困境”“道德义务”是同一类话题，不再调用模型。

- 新增标签后，只需归类新增的那几个。
- 没归类的标签按字面兜底：相同或互相包含算匹配；只共用词根（如“家庭”）的只算“有点兴趣”，不影响褒贬，因为“资本批判”和“资本家施舍”词根相同、立场相反。

**看法的状态**分开显示，避免“先记着某人印象不深，后来他却写出一篇深刻评论”这种矛盾：

- 尚未分析：读过，但还没让模型生成具体看法；
- 印象不深：推演结果确实平平；
- 有私人意见：已生成具体看法，还没对外说；
- 已表达：在谈话、书信或文章里说过。

“私下谈起”只有在推演里真的跟某个熟人谈了才算，否则记为“放在心里”。

**多维度看法**：生成私下看法时，技巧、思想、论证、情感、是否值得关注各自打分，可以互相矛盾，比如文笔出色、论证粗糙、不认同结论，却觉得作者值得关注。

- 另记一句“他心中的这位作者”。
- 以后再读同一笔名的作品，模型会拿到他以前每一次的看法，必须保留仍成立的判断，有修正时写明修正了哪一条、因为什么。不许编造“作者越来越成熟”这类没有依据的成长线。

**熟人关系**：在人物编辑里添加。关系有方向，写的是“此人对别人”，每条记类型、亲疏、见面频率、信任，以及谈不谈看法、肯不肯说出作者身份。

- 读完印象较深的人，会按见面频率和亲疏跟熟人谈起，对方因此有机会读到。说好的让人更想读，说不好的则少一点。
- 同一刊物的同事不填也会按“每周见、一般熟”算。
- “知道”和“愿意说”是两回事：作者身份只在此人自己知道、且对那个人愿意透露时才可能说出去。而且不会自动生效，只在概览里列为“可能的身份知情扩散”，由你确认或否认。
- 整理包格式也能带关系（`persons[].relations`），可以让外部 AI 从聊天记录里一并整理出来。

## 议题立场、文体偏好与作品主张（v0.9）

人物档案除了“关注、欣赏、反感”标签，还有两张小表：

- **思想立场**：议题、支持/反对/有保留、在意程度（低/中/高）、依据。例如米尔博：死刑，反对，高。
- **文体偏好**：解释密度、句子节奏、修辞密度等项目上的倾向，以及对不合口味写法的容忍度。只是倾向，不参与推演计算。

作品有一张“主张”表：作品在哪些议题上表明了什么立场。例如《生者与死亡》第三册上编：死刑，有保留（极端情况保留例外）。

推演时，思想上的赞同或反对由“立场 × 主张”对出来：同向算赞同，相反算反对，一方有保留算“部分赞同、有分歧”（立场越强越不满意折中）。结果写进阅读记录（赞同/部分赞同/反对），并影响褒贬；碰到他在意的议题，想法也会更强烈。议题名两边尽量用同一个词，或用“标签语义归类”把近义词归到一组。

生成私下看法时：

- 技巧、思想、论证、情感每一项都必须附证据卡编号或原文短摘，没有证据就记为“尚未判断”，不会从立场推出文笔好坏；
- 模型会拿到他实际读到的原文段落（只读了一部分的只给开头），按 12 项文体清单逐项看，只写有原文依据的项；“重复不等于冗余”要看段落本身判断；
- 另外输出认可的论点、分歧（标出关键分歧）、是否仍尊重作者、之后会继续追读/想争论/不再关注。

两张表和主张都可以点“✦ 让 AI 起草”：只添加还没有的条目，高亮显示，检查后再保存。整理包格式也支持 `stances`、`stylePrefs`、`claims` 三个字段。

## 名声拆成知名度与评价（v0.20）

以前“笔名声誉”只有一个数：好评加、批评减，把“有多少人知道”和“别人怎么评价”混在一起——被五家报纸批评反而变“声名狼藉”，四篇好评就“声誉卓著”；读者来信 82 封和 20 封加的分一样。现在每个读者圈子分两行：

- **知名度**（有多少人知道这个署名）：无人知晓 → 有人听说 → 开始受到关注 → 小有名气 → 颇有名气 → 声名远播。书评、论战、书讯、短讯都会让人知道，**批评也一样**；乘刊物影响力；读者来信按封数取对数（82 封比 20 封多，但不是四倍）；转载按条数；越有名，再多一篇的增量越小。
- **评价**（表态的人整体偏好还是偏坏）：尚无评价 / 评价平平 / 口碑不错 / 备受推崇 / 颇受非议 / 恶评如潮 / 褒贬不一。按书评、论战、书讯的分量取**加权平均**，不累加；“备受推崇”“恶评如潮”要表态够多才给。
- **点格子**看这一格由哪些已入账的反响构成、各加了多少；鼠标停留看具体数值。
- **名声体检**：已入账的反响没算进任何笔名（没关联笔名、笔名已不存在、和作品署名不一致）时，概览页提示，可以一键“按作品的署名重新关联”。
- 推演里“名气越大越多人留意”改用知名度（批评带来的知名度也算），评价不再影响接触概率。注入主对话写成“文学圈：小有名气，口碑不错”。

## 刊物周期、约略日期、不署名的书讯、题材兴趣（v0.19）

- **AI 核对刊物资料**（“人物与刊物”页，调用 1 次）：核对出刊周期、出刊日、圈子、倾向、影响力是否与当时相符，只列有出入的，附依据和把握。模型不联网，采纳前请核对。“采纳并重排”会改资料，并按新周期重排这家刊物上还没入账的推演反响（已入账的不动）。手动改刊物的周期/出刊日并保存时，也会问要不要重排；用整理包改了刊物周期/出刊日，会自动重排。
- **月刊、半月刊没填出刊日时，日期只是约略**：账本里标“约 7 月号”，注入主对话也写“约 7 月号”，推演理由里注明是按每月 1 日（半月刊 1、15 日）推算的。在刊物资料里填了出刊日就不再标约略。
- **书讯、短讯多半以刊物名义不署名**（书讯约六成五、短讯约七成五、书评一成五、论战极少）：推演里仍记着是谁写的、按他的看法写，但版面不署名，账本显示“《某刊》（未署名，执笔：某某）”，注入主对话只写“（未署名）”，写稿时用刊物口吻、不透露执笔者。
- **题材兴趣重新计算**：以前命中一半标签就算满分，现在边际递减、并看命中占作品题材的比例——只沾一两个边的落在三到五成，正中核心才到七八成以上。只影响之后新推演的部分，已有的记录不变。

## AI 查人物关系（v0.18）

“人物与刊物”页的 **AI 查到的人物关系**，或关系网里点人物后的 **✦ AI 查他的关系**（各调用 1 次）：让 AI 按它记得的史料，找出人物表里这些人彼此之间截至今天的关系——谁和谁是朋友、通信、决斗后和解、在哪次聚会见过，以及关系从何时开始。

- 只查人物表里的真实人物；虚构人物之间、虚构与真实人物之间不查。已有的、你拒绝过的、截至今天还没开始的不收。
- 每条标明把握：有明确史料 / 很可能 / 推测，附依据和出处。“有明确史料”的采纳后依据记为“史料可考”，其余记为“推测”（图上画虚线）。
- **模型不联网**：它给的史料只是记忆，可能记错日期或张冠李戴，依据前面都标着“AI 提供，未联网核实”。一律进待确认，你点“采纳”才写进人物关系；拿不准的点“当推测采纳”。也可以一键采纳全部“有明确史料”的。
- 顺带推荐不在人物表里、但和表里多人有往来、能把消息从一个圈子带到另一个圈子的“中转人物”，放进“AI 推荐的新人物”，标“关系中转人物”。

## 独立 API 修正（v0.17.1）

- 密钥栏不再用浏览器的密码框：以前浏览器可能把保存的登录密码自动填进密钥栏（还会把用户名填进地址栏），导致 401。现在是普通输入框加遮挡，可以点“显示”核对；密钥前后的空格、换行和多余的“Bearer ”会自动去掉。
- 模型名旁边有“获取模型列表”：向接口读取可用模型（GET /models）。读到后输入框换成一个下拉框直接选；列表里没有的选“手动输入…”。
- 测试连接改为最多输出 400 token（推理型模型 20 token 不够思考，会返回空内容）；空内容时说明原因。401/404/402/429 报错附带检查提示，401 时显示插件里存的密钥末四位。

## 人物关系网（v0.17）

- **按日期画**：顶部“截至”可以回看任意一天，只画那天有效的关系（关系的“从/到”日期）和那天之前已经发生的传递。
- **三类关系分开**：私人关系（朋友、家人、通信、师友）、文学与工作（编辑、同事、论敌）、社交场合（沙龙、见过面），可以分别开关。新增关系类型“见过面（共同会面）”，适合“5 月 13 日茶室同桌”这种只有一次会面、不算熟的情况。
- **关系的依据**：每条关系可以注明依据（史料可考 / 剧情里发生过 / 推测）和出处。推测的画虚线；同刊同事（推演自动算的）默认不画，可以勾出来，画点线。
- **方向**：只有一方写了的关系画箭头（A 把 B 当熟人不等于 B 也这样）；勾“双方都算”（家人默认）就两边都生效，推演里双方都会谈起。反过来的那一方不默认会说出身份与私事。
- **读过作品 ≠ 认识作者**：只有与主角有私交的人才连到主角。
- **点人物**：看他的一度关系、二度关系（经由谁），以及他自己是怎么接触到主角作品的。
- **点连线**：看两人之间两个方向的关系、依据，以及截至当天实际传过的话（谈起作品、可能泄露身份或私事）。
- **两人之间的信息路径**：选两个人，列出三跳以内的关系路径；每一跳标出推演里是否真的谈起过（⇒）还是只是有关系（→）。有路径不等于传过话；目标人物自己读到作品的渠道也会列出，不把他读到归功给路径上的人。
- 隐藏没有连线的人；整理包的 relations 新增 `mutual`、`basis`、`evidence`。

## 正确性与注入预算（v0.16）

- **见报 ≠ 主角读到**：设置“主角知道什么”有三种：①常读的报刊当天读到，其余（包括各报转载汇总）靠剪报几天后知道；②见报当天就知道（旧规则）；③**只算我标了读到的**——不看报、没有剪报服务的主角选这个。剧情里录入的、转到主角手上的读者来信不受限。整理材料时，聊天里提到了推演出来的某篇文章（同一作品、同一作者、日期相差十天内），会对上那一条并标为“主角已读到”，不另记一条，回滚重推后也保留。账本里没读到的标“主角还没读到”，可以手动点“主角已读到”。没读到的文章不进“主角已知的反响”；世界书作品条目里照样列出（别人可能读过），但标明主角还没读到。
- **世界书不写未发表的作品**：没有发表日期、或发表日期还没到的作品不进世界书。
- **同一天改写也会回滚**：改写、换回复时，日期没变还要比对正文。只改几个字不动；同一天但事情大改（相似度低于六成），照样回滚重推。
- **每 N 楼自动推演失败或被跳过时**，下一楼再试，不必再等 N 楼。
- **注入预算**：传闻只注入热度最高的几条（默认 5）；世界书每个人物条目有字数上限（默认 1500 字），超出时先省略最早读过的作品。
- **“只知道不晚于某天”的作品**可以填“最早可能的日期”，推演在这两天之间取，不再固定往前 20 天。

## 认知对照、主角的自我认知、公众形象（v0.15）

“人物与刊物”页的 **认知对照**：同一类事情（文风、思想倾向、身份背景、创作动机……）一行，把各方并排放在一起：

- **主角自认 / 对外说法**：“主角自认”只是他心里怎么看自己，谁都不会因此知道；“对外说法”是在文章、序言、访谈里公开说过的话，从那天起，生成看法时读者会知道“作者自己这么说过”（可以信也可以不信），认知可以标“本人说的”；写稿的人也可以引用或反驳。
- **主角以为**（反向认知差）：主角以为某人或某个读者圈子怎么看他。程序和对方实际的认知、圈子的公众形象比对，对方没形成这种看法、或字面对不上的，标“有出入”。世界书里这个人的条目会写上“主角以为他觉得……”，并提醒以他实际的看法为准，让误会在对话里自然显露。
- **别人的认知**：每人每类取截至当天最新的一条，更早的折叠起来；误解、传闻会标出。剧情里明确说出口的看法可以“手记一条”，同样核对来源（“确知”对不上他知道的事就降为“推测”）。
- **各读者圈子的公众形象**：按圈子让 AI 依据当时的公开材料（见报文章、读者来信与剪报、作者的公开说法、传闻）整理流传的说法，每个圈子调用 1 次。私信、私事、主角的心里话都不会进去；每条必须注明依据，没有依据的不收；材料不到三篇不能说“普遍这么说”，只有传闻支持的只算“个别说法”。整理过的会写进世界书“署名的公众形象”条目。
- **截至某天**：可以回看任意一天的情况；**只看有出入的**只留下有问题的类别。
- **✦ AI 对照分析**（调用 1 次）：把表里所有内容交给 AI，找出外界误判、主角不知道的看法、主角以为错了、公开与私下不一、各方分歧，标出严重程度。只是分析，不改动任何人的认知。
- 公众形象和对照分析跟着楼层回滚。整理包新增 `selfImage`、`assumed`、`perceptions` 三个字段。

## 认知差：谁知道主角的什么（v0.14）

模拟器知道的，不等于角色知道。v0.14 把“主角的私人信息”和“谁知道”分开记：

- **主角的私人信息与知情者**（人物与刊物页顶部）：身世、国籍、母语、成长经历、知识背景、某部作品的创作意图……每条登记知情者、从哪天起知道、怎么知道的（亲口告诉 / 书信 / 听人转述 / 亲眼所见 / 自己推断）、信不信。作品编辑框里有“＋ 创作意图”，默认谁都不知道。勾“知情者绝不外传”的，推演不会出“可能说出去”的候选。
- **生成看法时只给知情者**：提示词里只列这个人在当天之前确实知道的事，并明确告诉模型“他不知道别的，不要替他猜中”。不知道笔名背后是谁的人，连“这是勒鲁的私事”这层联系也不给。
- **他对作者的印象**：生成看法时顺带写出这个人对作者的几条认知（身份、文风、意图、为人……），每条标明是确知、本人说的、推测、传闻还是误读。标成“确知/本人说的”却对不上他真正知道的事，自动降为“推测”。认知显示在看法详情和人物推演页“他知道什么 / 他怎么看作者”里，世界书人物条目也会带上。
- **写稿**：知情者写私信时可以提到他知道的事；公开文章一律不写出私事。不知情的人写稿时什么私事都拿不到。
- **幕后补完**：AI 补写幕后时会收到每条私事的知情者名单，不能让别人凭空知道，也不能让它自行传开。
- **私事外传只出候选**：知情者和别人谈起主角时（关系里勾了“可能说出作者身份与私事”的），推演可能认为他提到了某件私事，概览页列出来由你决定：“确有其事 / 说了但他不信 / 没有”。不会自动生效。
- 回滚到某楼时，私事外传候选恢复到当时；被撤掉的阅读记录对应的认知一起撤掉。整理包新增 `privateFacts` 字段。

## 报纸版面预览、年代档案按季度刷新（v0.13）

- **报纸版面预览**：账本页的“报纸版面”，或某条反响“更多”里的“在报纸版面上看”。选刊物和日期（也可以把一周合在一版），把已入账、主角看得到的文章排成当时报纸文艺栏的样子：报头（刊物“原文刊名”，在刊物资料里填）、法文和中文日期线、栏目、标题、正文、署名，三栏排版。真实人物默认只有“立场摘要”，标成“推演摘要，非原文”；没写正文的只排概要。可以在新窗口打开（方便截图或打印成 PDF），也可以下载 HTML。
- **法语为主、中文为译文**：版面可以切换“法语”（默认）、“法语＋译文”（每篇后附中文译文）和“中文”。法语稿由 AI 依据中文稿还原成当时的报刊法语（一版一次调用，按长度分批），人名、刊名、作品名用资料里的西文原名：作品的写在“别名”里，刊物的写在“原文刊名”里，人物的写在“别名”里。还没生成法语稿的文章先排中文并注明；中文稿重写后法语稿作废，需要重新生成。
- **年代档案按季度刷新**：设置“年代资料”里选每季度（默认）、每月或不刷新，到期时自动刷新（默认，每期调用 1 次 AI，并先检索维基百科）或只提醒。故事推进到新的一期时，按新日期重新生成档案，并特别写出本期新出版的书刊、创刊停刊的报刊、文坛和社会大事（“本期新事”），参考上一期档案保持连贯。旧档案的要点留在“年代 · 往期档案”里。

## 推演的时间与知情边界（v0.12）

- **主角知道什么**：见报的文章从见报那天起主角知道；寄给主角的私信收到那天起知道；别人之间的私信（书信簿里的第三方信件、整理包里写了别的收信人的私信）主角不知道，不注入主对话，账本里标“主角不知道”，等你点“主角已得知”填上日期才算。写稿人也只看得到见报的文章和自己写的东西。
- **不读未来的记忆**：生成某人的私下看法时，只给他在这次阅读之前已经形成的旧看法。
- **交谈按交谈那天算关系**：读完之后先定下哪天谈起，再看那天两人的关系是否有效（读完时还不认识、但一个月内结识的，可能在结识后谈起）。
- **引文核验**：私下看法里的每条引文都要在原文里逐字找得到（允许用省略号跳过中间），找不到的维度改为“尚未判断”；只读了开头的人，引文只能来自开头；没有原文时只认证据卡。文体评语没有原文就不留。
- **日期精度**：只知道旬、月份或“不晚于”的作品，推演在可能的范围内取一个确定的日子，并在“为什么”里写明，不把它当成确切的首发日。
- **不定期刊物**：可以填“已知出刊日期”，评论只落在这些日子；没填的，推演出的评论标“请核对”，不自动入账。
- **阅读程度不详**：只有署名反响、没有阅读记录时，补的是“读过，程度不详”，不再推断读完。整理包里没写 read 的阅读记录也按“程度不详”。
- **大报不再默认人人常读**：没填“常读刊物”的人，影响力 4 级以上的大报只按“偶尔翻到”算（概率低得多）。

`test/regress.js` 用 1890 年剧情的固定情形做回归测试，包括“时间旅行测试”（逐日推演、每 14 天推演、分段回溯三者对比，并检查任何时刻都没有未来的事件提前出现）。`npm test` 会一起跑。

## 私信寄进书信簿、时间线、关系网（v0.11）

- **私信寄进书信簿**：入账并写好正文的私信，自动作为“寄给主角”的来信放进书信簿（设置“书信簿联动”里可关）。账本里私信的“更多”也有“寄进书信簿”按钮。用书信簿自己的建信函数，编号、暗号、分段和手写的信一样；收信人取酒馆里你的名字。同一条只寄一次。需要书信簿插件正在运行（读进来的备份文件不能写回）。真实人物默认只写“立场摘要”，那种不寄。推演回滚时，已经寄进书信簿的信不会被收回，请在书信簿里自己删。
- **作品反响时间线**：作品卡片上的“时间线”。横轴是日期，泳道分见报评论、私信、来信·转载、读到、熟人谈起、幕后；颜色表示褒贬，空心是只读了一部分，竖线是接触到没读。上方是累计读者。鼠标停在点上看详情；下方可以按时间列出全部。只显示到当前故事日期为止。
- **人物关系网**：“人物与刊物”页顶部的“人物关系网”。节点颜色是与主角的私交，大小是读过主角作品的多少，外圈表示知道笔名是主角；线分与主角的私交、熟人关系、谈起作品（箭头指向听的人）、可能泄露身份四种，可以分别开关。拖动人物挪位置，鼠标停在人物上只显示和他相连的线。

## 世界书、撤销、原文存储（v0.10）

- **写进世界书**：设置“世界书”里打开后，人物条目（立场、与主角的私交、是否知道笔名真相、读过哪些作品、私下怎么看、对作者的印象）和作品条目（只写公开信息与已见报的反响）写进世界书“报刊回声”（可改名）。聊天里提到名字才进入上下文。数据有变化后几秒自动同步，也可以在“人物与刊物 · 世界书”里手动同步。只改动标题以【报刊回声】开头的条目；本聊天还没绑定世界书时自动绑上。
- **撤销**：应用整理包、txt 导入、全部入账/驳回、逐条写稿、一键推演（含自动推演）、回溯、归类标签、重写幕后、加入推荐人物、按新资料重推、删除人物/作品/刊物/笔名、清空数据之前，都会留一个还原点。标题栏的 ↶ 撤销最近一步（最多 6 步，刷新页面后清空）。
- **按新资料重推此人**：人物编辑框里的按钮。撤掉此人推演出的、还没入账的阅读和反响（以及由此产生的追读、推荐、印象），按新资料重新推演到今天。已入账的和手动记录保留。
- **作品原文存在浏览器本地数据库**（IndexedDB），聊天存档里只留字数，聊天文件不再因为原文变大。导出存档时原文会一起带上；用存档恢复时会自动挪回本地数据库。换浏览器或清空浏览器数据会丢原文，请用“导出存档”备份。
- **等主对话生成完再调用模型**：用酒馆当前连接时，如果主对话正在生成，插件的模型调用会排队等它结束（控制台里能看到等了多久）。独立 API 不需要等。

## 每 N 楼自动推演、AI 推荐新人物（v0.9.7）

- **每 N 楼自动推演**：设置“AI 补完”里填“每聊满多少楼自动推演一次”（0 = 不按楼数）。每聊满 N 楼，在 AI 回复完之后自动跑一次“一键推演到今天”，再按“一键推演后让 AI 补完”的设置调用 AI（受“每次最多调用 AI”限制）。自动跑时不弹确认，过程在控制台里看。删了楼会重新计数。可以选“延迟几楼”（默认 5）：只按最新几楼之前的剧情推演（故事日期、给 AI 看的聊天近况都不含最新几楼），这次推演和 AI 补完的结果并入之后的回滚点，重roll、改写、删掉最新几楼不会把它撤掉。用这个时建议把“故事日期 · 自动推演”设成“不自动”。建议用独立 API，免得和主对话的生成抢同一个连接。
- **AI 推荐新人物**：AI 补完时，按作品的刊物、读者圈子、题材和主张，推荐当时真实存在、可能读到作品的人，附推荐理由、接触途径、立场和“把握大小”。只放进“人物与刊物”页顶部的待确认：点“加入人物表”才加入，并立刻参与到今天为止的推演（不调用 AI）；点“不要”以后不再推荐此人。有新作品或距上次满 30 天才推荐，每次占 1 次调用；也可以手动点“现在推荐一次”。

## 什么时候推演（v0.9.6）

插件从聊天里认出故事日期后，先只记下“故事到了哪天”（标题栏会显示“推演到 某日”）。推演的时机在设置“故事日期”里选：

- **故事时间每过 N 天推演一次**（默认 14 天）：攒够天数才推，一周、半个月、一个月都可以；
- **每次识别到新日期都推演**；
- **不自动**：只在你点“一键推演到今天”时推。

推演间隔不影响结果：同一份存档按天推、按 14 天推、按 30 天推，谁读了什么、哪天读、态度如何完全一样；只影响这些反响多久之后出现在待审核和主对话里。“一键推演”总是推到最新的故事日期。

## 一键推演与幕后补完（v0.9.4）

“概览”右上角的“一键推演到今天”分两步：

1. **推演**（不调用 AI）：所有作品 × 所有人物推到当前日期，定下谁在何时读了什么、态度如何、跟谁谈起、有没有公开写或写信。
2. **AI 补完**（按设置，开始前告诉你要调用几次）：
   - 给新读者生成私下看法（想法强烈、真实人物、私交深的优先，有上限）；
   - 补写“幕后”：沙龙里的议论、编辑部的盘算、书店里的情形、熟人之间的转述、他人之间的书信——聊天正文里没写到、主角不知道的事。每条标明“主角不知道 / 或许听说 / 知道”，并写出依据的推演结果和主角以后可能怎样得知；
   - 可选：给新入账的反响写稿。

幕后补完不能改变推演结果，不能凭空制造新的公开书评或寄给主角的信。补出来的传闻进入“坊间传闻”。幕后内容在“概览·幕后”里查看，可以删除或重写最近一期；改写、删除聊天消息回滚时一并撤回。

注入主对话时，默认只注入主角能知道的幕后条目；也可以改成全部注入（标明主角不知道，供叙事作暗线）。聊天里日期自动推进时默认不调用 AI，可以在设置“AI 补完”里打开。

## 成书的长尾与话题带动（v0.9.1）

报纸上的文章、连载过了发表期，就很少有人再去找。成书、单行本、小册子不一样，会一直在书店、图书馆、沙龙里流通。

- 推进日期时，长期流通的作品每个月都给“还没碰过它（任一版本）”的人一次机会；离发表越久，机会越小。
- 作者名气越大，机会越大；这个署名近两个月见报越多（书评、论战、转载，不论评的是哪部作品），机会也越大。所以一部话题作会带动旧书：没读过话题作的人，也可能去书店找这位作者的书。阅读记录的“为什么”里会写明是哪部作品带起的话题。
- 读过一部作品的人再去找同作者的其他作品，仍由原来的“追读”“主动去找”机制负责。
- 作品资料里可以指定“发表后是否长期有人读”和“流通到”（售罄、绝版日期）。

## 与书信簿（st-epistolary）联动

只读，不改动书信簿的档案。**信里的内容默认不算已发生的反响**，只作为辅助线索，由你逐条决定：

**档案来源**有两种：装了书信簿插件时读实时档案；也可以在“导入”页直接**读取书信簿导出的备份文件**（.json），不装插件也能用。

- 读了备份就优先用备份，可以随时“卸下备份”。
- 备份只放在内存里（可能有好几 MB，不适合存进聊天），刷新页面后需要重新读取。已处理的线索和已导入的原文会保留在本聊天里。
- 备份里有多张角色卡的信时，可以选择扫描哪一张，默认是当前角色卡。

**信的日期**：书信簿里很多信没填写信日期，这时取事件记录里最早的“写成/寄出”日期。主角寄出的信，按对方“已读/收到”的日期算他得知作品的时间。

**作品匹配**：按书名和作品的“别名／外文名”找（例如 L’Aîné、Le Journal d’Ishida）。两三个字的短书名只在带书名号时才算提到。笔名只在第三方之间的信里算线索，因为写给主角的信里称呼笔名是常事。

**剪报汇编**（例如 L’Argus de la Presse 寄来的剪报）会被标出来，建议“送去抽取”：整封信会放进抽取文本框，由模型把里面已经见报的评论录入为已发生的反响，仍然要你勾选确认。

**文章稿**：书信簿“文章”文件夹里的稿子会单独列出，并按标题猜测对应的作品。可以导入为作品原文（设为原文、追加到原文，或新建作品），用来生成证据卡。


- **剧情日期**：概览页会显示书信簿推算的剧情日期，可以一键推进到那天。设置里可以开启自动跟随（只前进，跨度不超过上限）。
- **扫描线索**：在“导入”页点“扫描信件中的作品线索”。会找出当前角色卡下、不晚于故事日期、已寄出的信中提到作品名或笔名的段落。每条线索可以：
  - 记为对方已读过：进入阅读记录，再由推演决定他之后会不会写点什么；
  - 记为一封已发生的私信反响：进入候选，褒贬需要你自己改；
  - 忽略。
- **导入人物**：把书信簿的人物档案加入待合并。会保留“真实历史人物”标记，默认没有公开身份，需要你补充。

## 年代识别与检索

- **日期识别**：支持“1890年6月24日”“一八九〇年十月二十九日”“24 juin 1890”“1er septembre 1890”“June 24, 1890”“1890-06-24”。
  - 消息开头的日期和带星期的日期优先。
  - **日期只向前推进**：正文里回忆往事的日期（例如“1887年8月31日处决”）不会把时间拨回去。
  - 跨度超过设定天数（默认 120 天）的日期视为引述，忽略。
  - 消息里写的星期与实际不符时会提醒你。
- **地点**：根据最近的消息粗略猜测，可以手改。
- **维基百科检索**：按年份和地点检索，例如“1890 en France”“1890 en littérature”“1890 in literature”“1890年”。
  - 同一年份的页面会**自动剪掉当前故事日期之后的月份和条目**，避免年代档案剧透未来。
  - “检索当前年代”可以搜任意词条，查看摘要并加入年代笔记。
- **年代档案**：包括货币、报刊格局、活跃评论家、潮流、近期大事、报刊文体、时代用语、**禁止出现的时代错置事物**、季节系数。
  - 写稿时作为约束提供给模型。
  - 写完后自动扫描：命中禁用词，或出现晚于当前年份的年份，都会标出提示。
  - 档案里的真实刊物和评论家可以一键加入待合并。

> 维基百科在部分网络环境下无法访问。访问不到时，可以用“仅用模型知识生成”，或者在年代笔记里手动贴资料。

## 注入主对话

扩展会向主对话注入一段简短的“报刊现状”：故事日期、时代约束、笔名声誉、主角**已经知道**的反响、坊间传闻。同时告诉主模型：**列表以外的书评视为不存在，不得自行编造。**

排期中的文章、驳回的候选都不会注入。

## 真实历史人物

默认设置下，真实人物只生成**第三人称的立场摘要**，不替他写第一人称原话。如果你在设置里改为“允许拟写全文”，生成的文字仍应视为虚构。

## 写稿用的模型

- **酒馆当前连接**：直接用你正在聊天的模型。
- **独立 OpenAI 兼容 API**：填写地址、密钥和模型名，不占用主对话的上下文。

  - 写稿后的时代错置校验。

## 已知限制

- **只在模拟环境测试过，没在真实酒馆里跑过。** 推演逻辑和界面流程都在 Node / jsdom 里测过，但没有装进真实的酒馆运行。不同酒馆版本的 `generateRaw`、`setExtensionPrompt`、`loadWorldInfo` 接口可能有差异，遇到问题请打开浏览器控制台查看以 `[报刊回声]` 开头的报错。
- **推演只往前走。** 如果日期识别错了，可以删掉或改写那条消息让它自动回滚，也可以在概览页用“设为当前（不推演）”更正。已经掷过的骰子不会重掷，除非对某部作品使用“按新资料重推”。快照最多保留 40 个楼层。
- **书信簿的接口是按它当前的代码读的**（`globalThis.epistolary.store.archive`）。书信簿如果改了内部结构，联动部分可能失效，但不影响其余功能。
- **数量不保证与历史一致。** 推演结果反映的是你填写的人物和刊物，不是历史统计。觉得评论太多或太少，调“公开发表意愿”和各层级倍率。
